# injection_pilot.json 字段注释

> 产生脚本: `server/08_pilot_injection.py` (E4)
> 修正打分: `server/09_rescore_centered.py` (E5) → 去均值分数在 `centered_rescore.json`
> 实验日期: 2026-07-10
> 模型: Gemma-3-12B-IT L32 resid_post, AV/AR = kitft NLA L32 检查点, SAE = gemma-scope-2 w16k L0≈15

---

## 实验原理

往 SAE 残差 r = x − SAE(x) 中注入已知的 SAE 特征方向,测 AV 能否检测到:

```
r_α = r + α · ‖r‖ · ŵ_j
```

- α=0 → 纯残差(无注入,假阳性地板)
- α=1 → 注入信号大小 = 残差范数(约占激活范数的 ~12%)
- α=2 → 注入信号 = 2× 残差范数(约占激活范数的 ~24%)

## rows 字段 (80 行)

### 行的组织方式

- **α=0 行** (16 行): 对每个残差 idx 只做 **1 次 AV 生成**,然后对 4 个特征方向各打一次分
  → 4 残差 × 4 特征 = 16 行,但实际只有 4 次生成(同一段 explanation 复用)
- **α>0 行** (64 行): 每个 (残差, 特征, α) 组合做 **1 次独立 AV 生成**
  → 4 残差 × 4 特征 × 4 个 α = 64 行,64 次独立生成

```jsonc
{
  "resid_idx": 0,
  //   残差的索引(对应 acts_L32.parquet 的第 0 行)
  //   取值: 0, 10, 20, 30

  "token": ",",
  //   该位置的原始 token(从 parquet 的 "token" 列提取)
  //   仅用于人类识别,不参与计算

  "feature": 166,
  //   注入的 SAE 特征 ID(对应 gemma-scope-2 w16k 的特征索引)
  //   取值: 166, 443, 239, 490

  "alpha": 0.0,
  //   注入强度
  //   0.0 = 纯残差,无注入(假阳性地板)
  //   0.25 = 注入 0.25 × ‖r‖ 的特征方向
  //   2.0 = 注入 2.0 × ‖r‖ 的特征方向(最强)
  //   实际注入公式: r_α = r + α · ‖r‖ · ŵ_j

  "overlap": 0.1166,
  //   注入方向 ŵ_j 与原始残差单位方向 r̂ 的 cos
  //   即: ŵ_j · (r / ‖r‖)
  //   量化残差本身有多少分量已经在注入方向上
  //   值域 [-1, 1], 绝大部分在 ±0.1 附近(残差与 w_dec 基本正交)

  "explanation": "Article structure: informational/review format ...",
  //   AV 对 r_α 生成的自然语言解释(完整文本)
  //   α=0 时 4 个特征共享同一段 explanation
  //   α>0 时每行独立生成
  //   ⚠ 绝大部分是泛型模板("Article structure: ...")
  //     因为残差 + 注入信号仍然是离流形输入,AV collapse 成模板

  "cos_sig": -0.9464,
  //   ⭐ 核心检测指标(未去均值)
  //   = cos(AR.reconstruct(explanation), ŵ_j × target_norm)
  //   即: AR 从解释文本重建出的向量,与注入方向的余弦相似度
  //   理想情况(AV 检测到了注入): α↑ 时 |cos_sig| 应该上升
  //   实际结果: 平坦(0.92 → 0.92),AV 完全无感
  //
  //   ⚠ 重要: 这个值被均值方向混淆严重虚高!
  //   去均值版本见 centered_rescore.json → injection_rows[].cos_sig_c
  //   去均值后 α=0 地板从 0.92 降到 0.07
  //
  //   负号含义(如 −0.946):
  //   不是"AV 检测到了反方向信号",而是 w_dec 与均值方向反向对齐
  //   (f166 与均值 cos = −0.958),AR 默认输出在 +均值方向,
  //   所以 cos(+均值方向, −均值方向特征) ≈ −0.95

  "cos_res": -0.1073
  //   辅助指标
  //   = cos(AR.reconstruct(explanation), r)
  //   即: AR 重建向量与原始残差(不含注入)的余弦
  //   通常在 ±0.1 附近,说明 AR 重建跟残差几乎无关
  //   (佐证 E3/Pilot 2 的结论: 残差不可读)
}
```

## 如何正确使用这份数据

### ❌ 不要这样读

> "α=0 时 |cos_sig| = 0.92,说明 AV 不需要注入就能检测到特征方向"

这是**均值混淆的假象**。AR 对任何泛型文本的重建都落在均值方向附近,
而这 4 个特征的 w_dec 与均值对齐 ±0.9,所以 cos 天然就高。

### ✅ 应该这样读

1. **看去均值版本**: `centered_rescore.json → injection_centered_curve`
   - α=0 地板: mean |cos_sig_c| = **0.072**(接近零,假阳性干净）
   - α=2: mean |cos_sig_c| = **0.092**(仍然接近零,检测失败）

2. **检测曲线平坦 = AV 对注入信号零敏感性**:
   不论注入多少信号(3%~24% 激活范数),AV 都生成同一句模板,
   AR 重建出的向量与注入方向无关

3. **α=0 地板 0.92 本身是最重要的发现**:
   它暴露了贯穿 E1-E4 的均值对齐混淆,直接触发了 E5(去均值修正)
