# N6+、J1 与 J2 实验通俗说明

> 本文接着《N1–N5实验通俗说明》，解释本项目后续的 **N6+、J1 和 J2**。这里的 N6+ 主要回答“自然语言解释中的候选内容，究竟是不是当前样本自己的信息”；J1 和 J2 则回到项目最初的双向目标：让 NLA 和 SAE 互相帮助。
>
> 如果只记住三句话：
>
> 1. **N6+ 证明了 NLA 文本中的一部分内容确实是当前样本特有、并且会影响模型后续预测的内容。**
> 2. **J1 初步显示 NLA 可以帮助提出 SAE feature 的解释假设，但目前还没有证明它比 SAE-only 稳定地更好。**
> 3. **J2 发现，把 SAE 重建结果直接再交给 NLA，并不会简单地产生“更好的解释”；这种串联会改善某些几何指标，却平均损害因果保真度。**

---

## 1. 先回顾：NLA 和 SAE 分别在做什么

### 1.1 NLA：把激活翻译成自然语言，再翻译回来

模型在处理文本时，会在内部产生很多激活向量。它们是一长串数字，人类无法直接阅读。

NLA 大致做两件事：

1. **AV（Activation Verbalizer）**：把激活向量翻译成自然语言解释；
2. **AR（Activation Reconstructor）**：只看这段解释，再重建出激活向量。

可以把它想象成：

> 模型脑中的状态 → 用文字描述 → 根据文字恢复模型状态。

这里的文字并不一定是人类意义上的“完整解释”。它可能描述了模型正在关注的对象、上下文、候选词或下一步预测方向。

### 1.2 SAE：用稀疏特征表示激活

SAE，即 Sparse Autoencoder，可以理解成一个“稀疏字典”：

- 编码器把激活向量拆成若干 feature；
- 通常只有少量 feature 被激活；
- 解码器再用这些 feature 的方向重建原始激活。

例如，一个内部状态可能同时包含：

- 人名信息；
- 句法结构；
- 语言种类；
- 某个主题；
- 下一 token 的预测倾向。

SAE 希望把这些混合信号拆成若干相对稀疏的“内部成分”。

### 1.3 为什么还要做 N6+、J1、J2

N1–N5 已经告诉我们：

- NLA 的文本不是随便生成的泛型模板；
- 第三段候选内容很重要；
- 这些内容放回模型后确实会影响模型预测；
- 但 cosine 分数高，并不代表每一个样本都可靠；
- NLA 也没有证明全面优于 SAE-big。

因此后续要继续回答三个更具体的问题：

1. 候选内容到底是“通用格式”，还是当前样本独有的信息？
2. NLA 能不能帮助人类或自动系统解释 SAE feature？
3. SAE 提供的稀疏结构能不能反过来帮助 NLA？

N6+、J1、J2 就分别对应这三个问题。

# 2. N6+：候选内容是不是当前样本自己的信息

## 2.1 N6+ 要解决的疑问

N1–N5 发现，NLA 解释的第三段（记作 `p3`）通常包含一组候选内容。这些候选看起来像是模型对下一个 token 或后续文本的预测。

但当时仍然有一个重要疑问：

> NLA 真的使用了当前样本自己的候选内容，还是只要看到“候选列表”这种格式，就能恢复得很好？

举个例子。假设原始激活来自一句关于天气的文本，NLA 输出了：

> 候选：`sunny`、`cloudy`、`rainy`、`windy`

我们不能只因为 AR 能根据这段话重建激活，就断定它理解了当前样本。也许 AR 只是学会了：

> 看到“候选：四个英文词”的格式，就生成一个看起来差不多的向量。

N6+ 的核心目的，就是把“样本自己的内容”和“通用格式”拆开。

## 2.2 N6+ 的基本办法：换掉候选词

实验对每个样本准备两种 p3：

### A. true candidates：真实候选

保留这个样本原本的候选内容。

这相当于问：

> 用当前样本自己的候选内容，模型能恢复多少有用信息？

### B. cross-matched candidates：匹配后替换的候选

从另一个样本中拿来候选内容，但尽量匹配：

- 来自相同来源；
- 候选数量相同；
- 文本长度和格式相近；
- donor 和 recipient 不是同一行、同一文档或同一内容组；
- 不包含相同的标准化候选字符串。

这样，替换前后基本保留了：

- p3 的整体结构；
- 引号和文本格式；
- 候选数量；
- 大致长度；
- 语料来源。

真正被改变的主要是：

> 候选内容究竟是不是属于当前样本。

这就像做医学实验时的“匹配对照”：两组尽量相似，只改变一个关键因素。

## 2.3 N6+ 的数据规模和范围

N6+ 使用了全新的英文 Pile 真实语料，而不是 N4/N5 旧样本：

- 先准备 501 个候选内容组；
- 其中 434 个符合固定的 AV 文本格式；
- 最终使用 400 个样本；
- 来自 13 个 Pile 来源；
- 每个样本来自不同文档和内容组；
- 候选数量为 4、5 或 6 个；
- 所有样本都是真实内容 token，不是聊天模板或空白 token。

这里需要特别注意：

> 结论适用于“能够被当前固定 AV 格式解析的 Pile 内容 token 子集”，不能直接外推到所有模型、所有层、所有语言或所有位置。

## 2.4 N6+ 还测了什么

除了替换候选，还准备了其他版本：

- 原始完整文本；
- 只保留 p3；
- 去掉候选但保留 anchors；
- 去掉 anchors 但保留候选；
- 去掉所有引号里的内容；
- 只保留 p1/p2；
- SAE-big 的重建结果；
- zero ablation 和 identity 对照。

其中：

- **identity** 表示不改变激活，用来验证实验本身没有产生伪差异；
- **zero** 表示把相关激活完全抹掉，用来估计“原始状态对模型预测有多重要”。

## 2.5 N6+ 的关键结果一：真实候选比错误候选更有因果作用

N6+ 最重要的比较是：

> `p3_true` 和 `p3_cross_matched` 放回模型后，谁能更好地恢复原模型的后续预测？

结果显示，保留真实候选的版本明显优于替换成其他样本候选的版本：

- `G_specific = +0.117954`；
- 95% 区间为 `[+0.102860, +0.133995]`；
- 直接的 KL 差异约为 `+1.827883 nat/row`；
- 区间为 `[+1.591758, +2.074946]`。

这里的 KL 可以通俗理解为：

> 原始模型的预测分布，和改动后的模型预测分布相差多少。

KL 越小，说明改动后的激活越接近原始模型状态。真实候选能让 KL 更低，表示它保留了更多当前样本的预测信息。

所以 N6+ 排除了一个重要的替代解释：

> NLA 的效果不是单纯来自“候选列表的外形”，而是部分来自候选内容本身。

## 2.6 N6+ 的关键结果二：真实候选与下一 token 预测高度对齐

N6+ 还检查了真实候选和模型 clean 状态下的 next-token 分布是否匹配。

结果如下：

| 指标 | 真实候选 | 替换候选 |
|---|---:|---:|
| top-1 命中率 | 66.50% | 3.75% |
| top-5 命中率 | 84.00% | 11.75% |
| top-10 命中率 | 87.00% | 16.50% |
| top-50 命中率 | 95.75% | 35.75% |
| 实际 next token 出现在候选集合中 | 49.00% | 2.75% |

这说明：

> 真实候选不是任意词，而是与模型当前正在预测的下一步内容有明显联系。

但不能把它夸大成：

- 候选字符串是完整正确答案；
- 候选集合等于完整 continuation 的概率分布；
- 候选内容已经通过人类命题级事实验证。

它更准确的含义是：

> NLA 的第三段包含了模型当时的“预测状态”，尤其是下一步可能输出什么。

## 2.7 N6+ 的关键结果三：候选很重要，但不能说候选支配一切

N6+ 对不同内容做消融后，整体 causal recovery 大致如下：

| 条件 | 恢复比例 |
|---|---:|
| 原始完整重建 | 0.979493 |
| SAE-big | 0.978140 |
| p3 真实候选 | 0.974768 |
| p3 替换候选 | 0.856814 |
| 去掉候选 | 0.820385 |
| p12 | 0.795530 |
| 去掉 anchors | 0.775343 |
| 去掉所有引号内容 | 0.367074 |
| zero | 0 |

直观上看：

- 去掉候选会明显损失；
- 去掉 anchors 也会明显损失；
- 同时保留 anchors 和候选时效果最好；
- 候选与 anchors 之间可能存在互补或非线性交互。

因此最稳妥的解释是：

> p3 是由 anchors、当前样本的候选内容和文本结构共同组成的预测状态编码。真实候选有不可替代的增量作用，但目前没有证据说明它是唯一或绝对主导成分。

N6+ 的 secondary endpoint 还明确不支持“candidate dominance”，也就是不能说“候选比 anchors 更重要”。

## 2.8 N6+ 的意义

N6+ 把项目的结论向前推进了一步：

N1–N5 说明：

> p3 很重要，并且具有因果效用。

N6+ 进一步说明：

> p3 中的真实候选内容本身也很重要，换成匹配的错误候选后，效果会明显下降。

所以可以把 NLA 文本理解为一种：

> **样本特异、与下一 token 预测对齐的自然语言 predictive-state code。**

但它仍然不是完整的人类语义解释证书，也不是“以后可以放心部署”的安全路由器。

## 2.9 N6+ 没有证明什么

N6+ 没有证明：

- NLA 全面优于 SAE；
- NLA 等价于或可以安全替代 SAE-big；
- centered cosine 可以作为可靠 router；
- 候选内容比 anchors 更重要；
- 候选内容代表完整命题或完整后续文本；
- NLA 文本对人类一定忠实；
- 这已经是 steering 实验。

# 3. J1：NLA 能不能帮助解释 SAE feature

## 3.1 J1 回到项目最初的问题

项目最初并不是为了单纯比较“谁的重建 cosine 更高”，而是想让 NLA 和 SAE 互相帮助：

- NLA 擅长生成自然语言；
- SAE 擅长提供稀疏、可定位的内部 feature；
- 两者结合，也许可以更好地解释模型内部机制。

J1 研究的是第一条方向：

> **NLA 能不能帮助我们给 SAE feature 生成更准确、更有用的解释？**

## 3.2 SAE feature 解释是什么

假设 SAE 的第 1234 个 feature 在很多句子中被激活。我们希望知道：

> 这个 feature 可能代表什么？

传统做法通常是：

1. 找出 feature 激活最高的几个文本片段；
2. 让解释者观察这些上下文；
3. 写一个 feature hypothesis，例如“与 Linux 命令相关”；
4. 在新的文本上测试这个假设是否能预测 feature 是否激活。

问题在于，几个文本片段可能很长、很复杂，人类或自动解释器容易忽略细节。

J1 的想法是：

> 让 NLA 先把激活状态翻译成短一些、结构化一些的自然语言描述，再把这些描述提供给解释者。

如果有效，NLA 应该能帮助解释者更快发现 feature 的共同模式。

## 3.3 J1 的实验材料

J1 使用了 45 个 SAE feature：

- 每个 feature 有 4 个 discovery positive contexts；
- 另外准备 held-out positive contexts；
- 每个正例配一个 feature 激活精确为零的 hard negative；
- 总共评估了 1,800 个正负样本评分。

所谓 held-out，就是：

> 不能只在看过的样本上解释得好，还要在新的文本上预测 feature 是否激活。

这是为了避免解释者只是记住了原来的句子。

## 3.4 J1 比较了哪些方法

J1 主要比较五种条件：

### 1. SAE_CONTEXT

只给解释者看 SAE feature 的高激活上下文。这是 SAE-only baseline。

### 2. NLA_ASSISTED

同时给出 SAE 上下文和 NLA 生成的辅助描述。这是 J1 最关心的组合。

### 3. NLA_CONTRASTIVE

提供更强调差异或对比的信息，测试“让 NLA 帮忙指出变化”是否有用。

### 4. NLA_MISMATCHED

故意提供不属于当前 feature 的 NLA 内容。这是错误信息对照。

### 5. NLA_ONLY

只使用 NLA 生成的描述，不给传统 SAE 上下文。

为了降低主观影响，J1 还让另一套评估模型 Terra 进行盲评。它不知道：

- 这个 hypothesis 来自哪个 arm；
- 哪个 feature 是真实目标；
- 哪些样本是正例或负例；
- 标注者是谁。

## 3.5 J1 的结果

主要结果使用 micro AP，数值越高越好：

| 方法 | micro AP | pairwise accuracy | Brier，越低越好 |
|---|---:|---:|---:|
| SAE_CONTEXT | 0.905301 | 0.888889 | 0.145098 |
| NLA_ASSISTED | **0.918582** | **0.906250** | **0.132426** |
| NLA_CONTRASTIVE | 0.907093 | 0.886111 | 0.142441 |
| NLA_MISMATCHED | 0.849382 | 0.800000 | 0.193581 |
| NLA_ONLY | 0.890284 | 0.881944 | 0.161125 |

表面上看，NLA_ASSISTED 是最好的：

- 比 SAE_CONTEXT 高 `0.013281` micro AP；
- pairwise accuracy 也更高；
- Brier 分数更低。

此外，NLA_ASSISTED 比 NLA_MISMATCHED 高 `0.069199` micro AP，说明“正确的 NLA 内容”比“错误配来的 NLA 内容”有用得多。

## 3.6 为什么 J1 还不能算成功

关键问题在于：

> NLA_ASSISTED 比 SAE_CONTEXT 的优势还不够稳定。

Assisted − SAE 的 micro AP 差异为：

- 点估计：`+0.013281`；
- 95% 区间：`[-0.004941, +0.035954]`。

区间跨过 0，表示当前数据不能排除“真实增益很小，甚至没有增益”。

而且不同标注来源的结果方向并不完全一致：

- Luna–Luna 子集为正；
- Fable–Fable 子集反而为负。

因此本轮正式裁决是：

> **REDESIGN_REPLICATE_BEFORE_CONFIRMATORY**

意思是：

> 这个方向值得继续，但先重新设计和复制，再进行昂贵的确认性实验。

## 3.7 J1 的几个重要限制

### 限制一：标签器可能有“同家族交流”问题

J1 的 NLA 描述和后续 hypothesis 主要由同一模型家族产生。即使 NLA 文本看起来帮助了评估，也不能完全排除：

> NLA 和解释器使用了某些彼此熟悉的表达方式。

所以后续需要加入非 OpenAI 家族的解释者或人工标注。

### 限制二：输入预算不公平

SAE_CONTEXT 平均约 684 bytes，而 NLA_ASSISTED 约 3,441 bytes，辅助条件看到了更多文字。

如果给 NLA_ASSISTED 更多文本，它的优势可能部分来自“信息量更多”，而不是 NLA 这种形式本身更好。

因此要加入 capacity-matched baseline：让 SAE-only 也获得相近数量的上下文和输入预算。

### 限制三：仍然缺少真正的外部因果端点

J1 当前主要测试的是：

> 这个解释 hypothesis 能否预测 held-out activation 是否激活。

但更强的验证应该进一步问：

- 删除这个 feature 后，模型输出是否按照 hypothesis 预测的方向变化？
- 放大这个 feature 后，模型行为是否变化？
- hypothesis 是否能预测真实的 downstream causal effect？

因此 J1 当前只是 discovery，不是最终确认。

## 3.8 J1 的正确结论

J1 可以支持：

- NLA 有潜力帮助 SAE feature 解释；
- 正确的 NLA 内容比错误配对的 NLA 内容更有用；
- Assisted 条件在整体上取得了最好的探索性分数；
- 值得继续设计新的异构、预算匹配、带因果端点的 J1。

J1 不能支持：

- NLA-assisted SAE 已经被确认优于 SAE-only；
- NLA 自动生成的 feature 标签一定正确；
- round-trip 分数本身就是标签真值；
- 当前结果可以直接用于部署自动 feature labeling pipeline。

## 3.9 后续 J1 应该怎么改

正式 confirmatory J1 至少应做：

1. 使用非 OpenAI 家族的解释者或人工重标；
2. 给 SAE-only 提供相当的上下文数量和字节预算；
3. 在新的、来源和 shingle 都隔离的 feature cohort 上进行；
4. 预先冻结 go/no-go 标准；
5. 加入 feature ablation、activation intervention 或 downstream behavior endpoint；
6. 对 AUPRC、coverage 和 calibration 一起报告；
7. 对完全不激活的 feature 标记为 not-testable，不把它们机械记为 AUC=0.5。

# 4. J2：SAE 能不能反过来帮助 NLA

## 4.1 J2 想解决什么问题

J1 是“NLA 帮 SAE”。J2 反过来问：

> SAE 的稀疏 feature 信息，能不能帮助 NLA 生成更准确、更稳定的自然语言解释？

最直观的想法是：

1. 先用 SAE 重建激活；
2. 把 SAE 重建结果交给 NLA 的 AV；
3. 再用 AR 把文字还原成激活；
4. 看看是否比直接把原激活交给 NLA 更好。

这就是 J2-P0 测试的串联路径：

```text
原始激活 x → SAE 重建 → AV 生成文字 → AR 重建激活
```

也可以写成：

`x → SAE(x) → AV(SAE(x)) → AR(...)`

## 4.2 J2 比较了四条路径

为了知道问题到底出在哪一步，J2 同时冻结并比较：

1. **Direct NLA**：`x → AV → AR`；
2. **Native SAE**：`x → SAE encoder → SAE decoder`；
3. **SAE-first loop**：`x → SAE → AV → AR`；
4. **Reverse order**：`x → NLA → SAE`。

同时测试 SAE-small 和 SAE-big。

这种设计很重要，因为如果只测试 SAE-first，看到结果变差后，很难判断是：

- SAE 本身损失了信息；
- AV 对稍微变化的输入很敏感；
- AR 重建进一步放大了误差；
- 两种系统串联时发生了相互不兼容。

## 4.3 J2 使用了什么数据

J2 复用了 N4 的数据：

- 200 个真实 content-token 位置；
- 101 篇文档；
- 其中没有聊天模板或空白 token；
- 通过冻结的激活 provenance 和 causal patch 流程完成检查。

总共完成：

- AV：400/400；
- causal cohort：200/200；
- 1,301 次 causal forward；
- 18 个预先按指标筛选的 case categories、35 个位置的 case bundle。

但是因为 J2 使用的是旧 N4 cohort，所以它是探索性机制审计，不是全新的确认性实验。

## 4.4 J2 的第一组结果：几何指标变好了

去均值 centered cosine 用于衡量重建向量的方向是否接近原始激活。结果如下：

| 条件 | SAE-small | SAE-big |
|---|---:|---:|
| 原生 SAE | 0.586929 | 0.640781 |
| SAE→AV→AR loop | 0.696417 | 0.736541 |
| 直接 NLA | 0.835669 | 0.835669 |

相对于原生 SAE，语言 loop 的 centered cosine 增加：

- SAE-small：`+0.109487`；
- SAE-big：`+0.095760`。

这说明 NLA 的语言瓶颈会把 SAE 重建结果拉向一种更接近数据流形的方向。可以把它理解成一种“自然语言先验”：

> 它会把不够自然、不够典型的向量，拉回模型常见的激活区域。

但是这个结果不能直接说明它保留了正确的样本信息。

## 4.5 J2 的第二组结果：稀疏 feature 身份反而丢失

J2 还比较了 SAE 的稀疏编码是否保持不变。

如果 SAE-first loop 真正保留了原始 SAE 的信息，重新编码后应该仍然激活相似的 feature，并且 feature 系数也相近。

但结果是，和直接 NLA 再编码相比，SAE-first loop 的：

- SAE-small support Jaccard 下降 `0.035807`；
- SAE-big support Jaccard 下降 `0.062617`；
- SAE-small code cosine 下降 `0.029295`；
- SAE-big code cosine 下降 `0.031677`；
- top-20 feature overlap 下降约 `0.720` 和 `0.735`。

通俗地说：

> 向量整体看起来仍然很像，但真正被点亮的 feature 集合已经发生明显变化。

这说明“raw cosine 很高”不能证明稀疏 feature 身份没有改变。

## 4.6 J2 的第三组结果：因果保真度平均变差

真正关键的是，把这些重建向量放回模型后，观察模型预测分布变化多大。

| 条件 | patch 位置平均 KL | aggregate causal recovery |
|---|---:|---:|
| 直接 NLA | 0.628851 | 0.947946 |
| 原生 SAE-small | 0.674448 | 0.944171 |
| SAE-small loop | 1.326531 | 0.890194 |
| 原生 SAE-big | 0.404879 | 0.966485 |
| SAE-big loop | 1.249711 | 0.896553 |

loop 相对 direct NLA 的 KL 增加：

- small：`+0.697680`，95% 区间 `[+0.467955,+0.988165]`；
- big：`+0.620861`，95% 区间 `[+0.320137,+0.980321]`。

KL 增加代表改动后的模型预测分布离原始状态更远。因此，虽然几何指标变好，因果保真度却平均变差。

这正是 J2 最重要的教训：

> **向量几何变好，不代表模型功能保留得更好。**

## 4.7 J2 的第四组结果：NLA 文本对微小输入变化很敏感

原激活 `x` 和 SAE 重建后的激活，raw cosine 通常都很高，大约在 `0.99` 左右。

但 AV 生成的文字变化很大：

| 指标 | SAE-small | SAE-big |
|---|---:|---:|
| token Jaccard | 0.3001 | 0.3330 |
| sequence similarity | 0.3319 | 0.3525 |
| quoted-token Jaccard | 0.1938 | 0.2390 |

也就是说：

> 两个数字向量整体方向很接近，但 NLA 生成的具体候选词、对象和命题可能已经换了一套。

这揭示了 NLA 的一个特点：它可能对激活中的细节非常敏感。微小变化会让语言输出跳到另一种解释或预测状态。

这既可能是缺点，也可能说明 NLA 在读取样本特异信息；关键在于必须用因果端点判断变化是否正确，而不能只看文字是否流畅。

## 4.8 J2 的局部案例说明了什么

J2 还按照预先冻结的指标筛选了一些典型位置进行案例研究。这些案例不能代表总体，但能帮助理解为什么平均结果复杂。

### idx75：局部成功

两种 SAE 宽度的 loop 都降低了 KL，有可能说明在某些位置，SAE 的稀疏投影确实帮助 NLA 稳定了某个局部状态。

### idx168：feature 相似度和因果效果相反

SAE-small 的代码相似度改善更大，但 causal fidelity 反而更差；SAE-big 的代码指标不一定最好，却在因果上更好。

这说明：

> sparse-code rescue 不能直接当作 causal safety 分数。

### idx185/186：相邻位置结果翻转

同一篇文档的相邻位置上，SAE-small 和 SAE-big 的表现发生翻转。一个宽度在某个位置有帮助，另一个宽度却可能造成灾难。

这说明位置和局部上下文会显著影响结果。

### idx122：数字和日期被改变

输出文字看起来流畅，但日期或数字身份发生变化；SAE-big loop 出现严重 causal failure。

这提醒我们：

> 流畅的语言不等于保留了原始样本的关键事实。

### idx130：因果好但文字未必忠实

某个 loop 的 causal KL 很低，但生成的自然语言解释在人类看来可能并不完全正确。

这说明：

> causal fidelity 和人类语义忠实度也是两个不同维度。

## 4.9 J2 的最终裁决

J2-P0 的裁决是：

> **不要按原样确认这套 SAE→自由文本 AV→AR 的串联设计。**

也就是说，J2 并不是证明“SAE 不能帮助 NLA”，而是证明：

> 最直观、最简单的串联方式没有成功，不能因为它改善了 centered cosine，就把它称为成功的 grounding。

J2 支持的结论：

- NLA 确实会把 SAE 重建结果拉向自己的激活流形；
- 串联后的几何相似度提高；
- 但原有 SAE 稀疏代码身份会丢失；
- 下游 causal fidelity 平均恶化；
- SAE 宽度、位置和组合顺序会造成明显异质性。

J2 不支持：

- SAE-grounded NLA 已经成功；
- SAE→NLA loop 优于 direct NLA 或 native SAE；
- 生成文字流畅就代表正确；
- 某几个 rescue case 可以证明整体 router 成功；
- J2 已经完成 steering。

## 4.10 后续 J2 应该怎么改

下一版不应继续简单地把一个完整 SAE 重建向量直接丢给 AV，而应考虑：

1. **结构化 grounding**：明确告诉 NLA 哪些 SAE feature 被激活、强度是多少；
2. **条件式解释**：要求 NLA 根据 feature identity 做可检验的预测，而不是只生成自由文本；
3. **反事实干预**：把某个 SAE feature 打开、关闭或放大，观察 NLA 是否预测到对应变化；
4. **全新的 held-out 数据**：不能继续只在 N4 数据上挑选 rescue/catastrophe；
5. **外部 causal endpoint**：最终要看 feature 干预是否真的改变了模型行为，以及 NLA 是否能预测这种变化。

在花费新的 GPU 资源前，还可以先用 CPU 分析当前 J2 数据，寻找可能的 pre-output 预测变量：

- SAE 的 fixed-point 稳定性；
- 激活范数；
- sparse code 改变了多少；
- 来源和语言；
- 候选内容身份；
- NLA 和 SAE 之间的分歧程度。

只有先形成冻结的规则，再在新数据上测试，才可能讨论 router 或 selective assistance。

# 5. 三组实验之间是什么关系

## 5.1 N6+：确认 NLA 文本内部确实有样本信息

N6+ 研究的是 NLA 本身：

> 解释文本中的候选内容是不是当前激活的特有预测状态？

答案是：是。真实候选比匹配错误候选更有因果作用。

## 5.2 J1：让 NLA 帮助 SAE

J1 研究的是第一种联合方式：

> NLA 的自然语言描述能不能帮助我们给 SAE feature 写出更好的解释？

答案是：有潜力，但当前 discovery 的增益小、区间跨零、存在标签器和预算混淆，不能确认。

## 5.3 J2：让 SAE 帮助 NLA

J2 研究的是反方向：

> SAE 的稀疏重建能不能让 NLA 的解释更可靠？

答案是：最简单的串联方式没有成功；几何变好，但稀疏身份和 causal fidelity 变差。

## 5.4 最终可以怎样概括

目前最准确的项目结论是：

> NLA 不是一个已经被证明全面优于 SAE 的替代品，SAE 也不是一个只要接到 NLA 前面就能自动提高解释质量的过滤器。二者各有所长：NLA 能提供自然语言形式的样本特异预测信息，SAE 能提供稀疏、可定位的内部表示。真正有希望的方向不是简单串联，而是让它们围绕明确的 feature identity、反事实干预和下游因果结果进行结构化协作。

# 6. 常见误解

## 误解一：N6+ 证明 NLA 生成了人类完全能看懂的真实解释

不对。N6+ 证明的是候选内容和模型 next-token predictive state 对齐，并具有下游因果效用。它没有完成 proposition-level human fidelity 验证。

## 误解二：N6+ 证明 candidates 比 anchors 更重要

不对。候选有不可替代的增量作用，但去掉 anchors 的损伤更大。当前最稳的说法是两者互补。

## 误解三：J1 分数最高，所以 NLA-assisted 已经成功

不对。`0.918582` 高于 `0.905301`，但差异的 95% 区间跨零，而且不同标注器子集方向翻转。J1 仍是 discovery。

## 误解四：J2 cosine 提高，所以 SAE 帮 NLA 成功

不对。J2 的 causal KL 平均变差。geometry、sparse-code identity、语言流畅度和 causal fidelity 必须分别评估。

## 误解五：J2 做了 causal patch，所以已经是 steering

不对。causal patch 只是把向量替换回模型，观察模型预测变化；真正 steering 还要主动构造方向并测试生成行为或任务行为。

## 误解六：N6+、J1、J2 已经证明二者可以直接部署成自动解释系统

不对。当前证据支持继续研究结构化协作，但仍需要跨模型、跨层、异构评估者、预算匹配和新的外部因果验证。

# 7. 最终总结

N6+ 是这一阶段最强的正向结果。它通过“匹配替换候选内容”的实验设计证明：NLA 第三段中的真实候选不是通用格式的副产品，而是与当前样本的 next-token predictive state 对齐、并且能够影响模型后续预测的样本特异信息。不过，候选和 anchors 是互补的，NLA 也仍有失败尾部。

J1 说明 NLA 有潜力成为 SAE feature interpretation 的辅助工具。它在探索性 discovery 中取得了最高的整体分数，且错误配对的 NLA 内容明显更差。但由于增益小、区间跨零、标签器可能同家族、输入预算不匹配，并且缺少新的 causal endpoint，J1 必须先重设计和异构复制。

J2 则提醒我们，SAE 和 NLA 不能靠最直观的串联方式自动融合。SAE 重建后再做语言化，确实会改善某些几何指标，却会改变稀疏 feature 身份，并平均损害下游因果保真度。下一步更合理的方向，是结构化提供 feature identity、强度和反事实干预信息，让 NLA 做可检验预测，再用新的 held-out causal endpoint 验证。

因此，N6+、J1、J2 共同把项目推进到了一个更清晰的位置：

> **NLA 已被证明能够携带真实的、样本特异的预测状态信息；但 NLA 与 SAE 的联合解释仍未完成。未来的关键不是继续比较一个漂亮的 cosine，而是设计能够被外部因果结果检验的结构化协作接口。**
